DS 2.1 · principles

Guiding rules

Eight design conventions that don't ship as code. They govern how new work is judged — content tone, layout density, spacing rhythm, icon usage. No Jira tickets attached; these are the standards engineering + design hold themselves to.

P1 Guideline

Product register, not brand register

Copy follows the product voice: utilitarian, terse, action-oriented. No marketing flourishes. Brand vs product for context.

P2 Guideline

Less card design on web

Sections separate via vertical spacing — no dividers, no framed wrappers. Cards are reserved for distinct entity tiles like tour rooms and water-mitigation areas.

P3 Guideline

No pill buttons — aligned radii

Action buttons use 8px on web and 16px on mobile (one step rounder than option 1's 12px, but still short of a full pill). Mobile cards round to 16px — buttons and cards now share the same radius for a calmer rhythm. Round icon-only nav buttons (back, more, edit) and badges keep their existing rounded shapes.

Web 8px Mobile 16px
P4 Guideline

8px gap between icon and text

On web buttons, the gap between leading icon and label is 8px. Equivalent to me-2 / ms-2 on a projected <svg-icon>.

Open 360°
P5 Guideline

Main actions get icons

Primary CTAs — Open 360°, Edit, Share, Request estimate — carry a leading icon. Subtle utility actions like Generate and More stay text-only so secondary surfaces read calmer.

P6 Guideline

Frequent utility actions stay quiet

Per-row download and edit actions render as icon-only 32×32 squares. The action is still recognisable, the row keeps more horizontal room for content, and the surface stays calm.

P7 Guideline

14px minimum body text

No 12px or 13px body copy on web. Body-sm is 14px. Badges keep the 12px caption size as the only documented exception. Specific component fixes — like alert font upgrade — are tracked separately in the tasks section.

P8 Guideline

Edge-to-edge cards · margined controls

Mobile cards lose their 16px side gutters and stretch to the device edges — wider tap targets, less wasted space, more native-app feel. Standalone controls keep their 16px side margins so they don't look orphaned: the standalone Share access pill on Project detail, plus the Projects search bar and the My projects / All office projects segmented tabs on Projects list. On the Projects list, the search bar and segmented tabs are also fully pill-shaped (both light and dark) so they read as iOS-native search/segment controls above the edge-to-edge cards below. Card radius stays at 16px.

Web · WEB-452 · In Progress Mobile · No equivalent

Yellow — small accents only

Yellow chartreuse #E5DF00 stays in the palette but loses every surface role. It is no longer used for primary CTAs, secondary actions, or promotional fills — those now belong to the olive + beige palette. Yellow returns as a pure accent on small surfaces only: decorations, small badges, counts, selected icons, and thin indicator stripes like the top-nav active underline. Large surfaces (sidebar menu rows, bottom-tab cells) stay neutral — yellow would overpower them. Treat it like a highlighter — high visibility, never a button, never a row.

T6
Web · WEB-473 · In Progress Mobile · Ticket pending

"NEW" tag is always green

Any NEW label flagging a freshly launched product feature — sidebar Initial Estimate, line item editor, future modules — uses the green badge style. Green is the most prominent tone in the palette and reads as "first time here". Other badge colours stay reserved for status (Done, In progress) or category (SOW, Latest). NEW is not for new messages, new orders, or pricing-tier framing — those keep their existing notification / status / commercial treatments. Text uses the shared text Badge recipe — Neutral/Ash 78%, sentence-case, 12px caption regular — matching every other status badge from PHX-1340. The dark-green text + 11px uppercase treatment from earlier drafts is retired. Mobile needs the same fix — a paired PHX subtask under PHX-1408 will follow.

Web · WEB-451 · In Progress Mobile · No equivalent

Alert font — 12 → 14px / 18px

First specific-component task derived from principle P7 (14px minimum body). The app-alert component (success / warning / error / info banners) currently renders at 12px / 14px — too small for state-critical messages. Bump to 14px / 18px in alert.component.scss, picked up automatically by all ~20+ feature templates that render <app-alert>. More component-level fixes (toasts, modal banners, anywhere else a 12 / 13px body slipped in) will land under the same epic as the codebase gets audited.

Alert text now renders at 14px / 18px — readable, breathable.
